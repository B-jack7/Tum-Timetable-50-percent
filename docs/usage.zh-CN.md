# Tum Timetable 使用说明

当前使用本应用自己的账号，不是学校身份认证。请设置独立密码，不要输入 TUM 或 Moodle 学校密码。新账号从空课表开始，旧版私人课程和订阅不会自动复制过来。

## 三步开始

1. 注册并登录。用户名为 3–32 位英文字母、数字、点、下划线或短横线，首位为字母或数字，保存时转小写；密码为 8–128 个字符，不要求大写或特殊符号，不去除首尾空白。
2. 点击页首“账号与绑定”，在弹窗中绑定订阅：TUMonline 进入 **Calendar → Publish**，复制私人 URL；Moodle 进入 **Calendar → Export calendar → Get calendar URL**。是否开放导出及可选范围，以你的实际账号为准。
3. 各粘贴一次，点击“绑定并同步”。课表按德国时间显示每周安排和地点，点击课程打开详情；“待办与截止”显示后续 Moodle 日历活动，可展开查看更多。页首“同步”可立即检查更新。

私人链接提交后立即清空，不存浏览器、不回显到页面或错误消息；服务端按账号加密保存。订阅链接不是直接授予学校账号权限，请保持私密。

## 课表与导航

桌面版恢复原私人版本的页首、下一次上课卡片、统计栏、每周网格及下方待办，可切换“全部课程”浏览课程卡片。手机版底部为“课表 / 待办 / 课程”；账号、绑定状态和退出登录均从页首“账号与绑定”弹窗打开。

这里只复用了界面布局与渲染工具，真实课程和活动来自当前账户各自绑定的订阅。课程详情显示日历实际提供的时间、地点和描述；日历未提供考核方式时会明确提示，不会套用旧私人版的考核信息，也不据此推断教师、学分或注册状态。

“已处理”只是在当前浏览器中保存的个人标记，使用当前账户范围内的不透明任务 ID，不保存课程内容或订阅链接，不代表 Moodle 已提交，也不跨设备同步。可用“查看已处理”重新显示这些活动。

## 自动更新与导出

开页检查订阅，前台每 15 分钟自动检查；回到前台时，过期的数据会再次检查。关闭后不在后台抓取。“账号与绑定”显示各来源的最近成功同步、数量及通用错误状态。

页首“导出”下载课程和 Moodle 活动的 ICS，Moodle 活动带提前 1 天和 2 小时提醒。待办区的“导入日历”只导出尚未标记处理、在未来且有明确时刻的活动；全天活动不补写具体截止时刻。导入后由你使用的日历软件及其通知设置处理。下载文件是当时的快照，变更后需重新下载。

日历事件不是成绩、考核规则或作业提交状态；外部作业平台的截止可能不在其中。同步成功也不保证来源包含所有课程或整个学期。

安卓用户可在 Chrome 选择“安装应用”或“添加到主屏幕”。主屏幕应用跟随网站更新，个人课表内容不提供离线缓存；浏览器只保留上述已处理任务 ID 标记。

## 开发与维护

使用 Node.js 24+，运行 `npm ci`、`npm start`。终端打印 HTTPS 本地地址，开发数据位于忽略的 `.local/`。`npm test` 执行测试；`npm run build` 将账号与日历 API、登录页、恢复后的课表界面及其适配器按明确允许清单构建为 Worker，不包含个人快照或 NLP 题库。配置见[本应用账号](auth-local.md)和[日历绑定](calendar-binding.md)。GitHub Pages 只能展示登录介绍，不能承载认证及私人数据服务。

学校 SAML 是需另行获批的未来选项，不是当前默认登录。旧版私人课表与练习站保持独立。仓库保留 91 题 NLP 双语作者源及备份兼容性，当前账户版不部署题库或同步练习进度；恢复课程详情布局不等于自动接入复习网站或 Moodle 材料。不要提交个人进度备份、日历链接、数据库或密钥。

README 中的新课表预览使用虚构数据展示布局，新账号不会获得这些示例课程；原私人版长截图仅作为所有者授权的历史预览保留。
