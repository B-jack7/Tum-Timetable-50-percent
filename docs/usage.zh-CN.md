# 使用说明

这是全新的公开 Tum Timetable 登录项目骨架，不含旧版个人课表或 Moodle 待办。每个账号从自己的空状态开始；登录不代表系统已经获得学校课程数据，也不会自动同步。真正的 TUM SSO 仍需要学校注册、获批的服务配置和单独部署的认证后端；GitHub Pages 只能用于空白静态客户端预览，不能部署完整登录服务。

## 本地查看

安装 Node.js 22 或更新版本后，在项目根目录运行 `npm ci`、`npm start`，使用同源 Node 认证服务器；学校登录需要按认证文档完成获批配置，缺少配置时保持禁用。`npm test` 执行测试。`npm run build` 只生成登录介绍页、认证界面文件、图标和 manifest；`npm run dev` 或 `npm run preview` 仅预览这些静态文件，不带课表、题库、账号页面、后端或 service worker，也不能真正认证用户。

认证后的应用界面保留课表、待办和课程入口，但新账号从空状态开始，不含旧版真实课表。“已处理”只代表个人标记，不等于向 Moodle 提交。日历导出需要用户自己的明确截止数据。旧版 PWA 生成器只作为历史工具保存在 `scripts/legacy/`，新登录版不启用其缓存，也不承诺私人数据离线可用。

## 编辑 NLP 题库

编辑 `authoring/in2361/content.json`，保留 91 个原题 ID 和双语、来源字段，运行 `npm run nlp:rebuild`。命令生成并更新 `public/courses/in2361/data.js`；预览展开的答案、语言切换及资料来源后，再构建和发布。普通文字和公式修改不需要原始 PDF。

浏览器学习记录不会随着代码迁移。换域名或设备前，在旧 NLP 站“资料与备份”导出 JSON，再到新站导入。备份格式、题目 ID 和存储键保持兼容，不要把个人进度备份提交到公共仓库。

整批 Python 双语维护工具保留了原始资料路径及依赖，不是任意电脑都能直接运行的生成命令；限制详见 [维护文档](maintenance.md)。真实账号数据、会话、密钥和未来的私人课表必须位于静态目录和公共缓存之外。
