# Tum Timetable 使用说明

当前使用本应用自己的账号，不是学校身份认证。请设置独立密码，不要输入 TUM 或 Moodle 学校密码。新账号从空课表开始，旧版私人课程和订阅不会自动复制过来。

## 三步开始

1. 注册并登录。用户名为 3–32 位英文字母、数字、点、下划线或短横线，首位为字母或数字，保存时转小写；密码为 12–128 个字符，不去除首尾空白。
2. 在“设置”绑定订阅：TUMonline 进入 **Calendar → Publish**，复制私人 URL；Moodle 进入 **Calendar → Export calendar → Get calendar URL**。是否开放导出及可选范围，以你的实际账号为准。
3. 各粘贴一次，点击“绑定并同步”。“课表”按德国时间显示每周安排和地点；“待办”显示最近 5 条 Moodle 日历活动。“同步日历”可立即检查更新。

私人链接提交后立即清空，不存浏览器、不回显到页面或错误消息；服务端按账号加密保存。订阅链接不是直接授予学校账号权限，请保持私密。

## 自动更新与导出

开页检查订阅，前台每 15 分钟自动检查；回到前台时，过期的数据会再次检查。关闭后不在后台抓取。设置显示各来源的最近成功同步、数量及通用错误状态。

“导出日历”下载 ICS，含提前 1 天和 2 小时提醒；导入后由你使用的日历软件及其通知设置处理。日历事件不是成绩、考核规则或作业提交状态；外部作业平台的截止可能不在其中。

## 开发与维护

使用 Node.js 24+，运行 `npm ci`、`npm start`。终端打印 HTTPS 本地地址，开发数据位于忽略的 `.local/`。`npm test` 执行测试；`npm run build` 构建账号与日历 API 的 Worker。配置见[本应用账号](auth-local.md)和[日历绑定](calendar-binding.md)。GitHub Pages 只能展示登录介绍，不能承载认证及私人数据服务。

学校 SAML 是需另行获批的未来选项，不是当前默认登录。旧版私人课表与练习站保持独立。仓库保留 91 题 NLP 双语作者源及备份兼容性，当前 MVP 不提供题库跳转。不要提交个人进度备份、日历链接、数据库或密钥。
